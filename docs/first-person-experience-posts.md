# 경험을 다룬 글에서 화자를 지우지 않는다

필자가 직접 겪은 일을 다루는 글(장애 대응, 취약점 발견, 마이그레이션 회고, 실험 기록)에 적용한다.
개념 설명글, 자격증 정리글, 레퍼런스 글에는 적용하지 않는다.

## 왜 이 규칙이 생겼는가

`2026-09-11-express-compression-zlib-memory-leak-cve-2026-87776` 초안이 계기다. 필자가 발견한
CVE를 다룬 글인데 7,657자에 1인칭 표현이 3회뿐이었고, 3절의 `Object.defineProperty` 함정은
필자가 직접 밟은 것인데 "이런 경우가 있으니 주의하세요"라는 일반 규칙문으로만 적혀 있었다.

`audit_humanizer.py --strict`는 통과했다. 기존 규칙은 메타 서술과 정형 문구만 잡기 때문에
**화자 부재는 검출하지 못한다.** 이 문서는 그 사각지대를 사람이 메우기 위한 체크리스트다.

## 규칙

### 1. 겪은 일을 규칙으로 번역하지 않는다

내가 밟은 함정은 내가 밟았다고 쓴다. 일반 규칙문으로 바꾸면 정보량은 같지만 글에서 사람이
사라지고, 독자는 "이 사람이 실제로 해 봤는가"를 판단할 근거를 잃는다.

| 바꾸기 전 | 바꾼 뒤 |
| --- | --- |
| `Object.defineProperty`를 써야 합니다 | 위 스크립트에서 `Object.defineProperty`를 쓴 이유가 여기 있습니다 |
| 재현할 때 RSS를 지표로 쓰면 판단이 흐려집니다 | 저는 재현 지표로 RSS를 쓰지 않았습니다 |
| Node v24.12.0에서 실행한 결과입니다 | 제가 Node v24.12.0에서 돌린 결과입니다 |

없던 감정이나 사실을 지어내라는 뜻이 아니다. **이미 본문에 있는 내용의 주체만 되돌린다.**

### 2. 발행 전 사람이 확인할 두 가지

- 이 글에서 필자가 직접 한 일이 몇 문장인가. 도입부 한 번 언급하고 끝이면 화자가 없는 것이다.
- 실패하거나 돌아간 경로가 본문에 남아 있는가. 정답 경로만 있는 글은 기록이 아니라 문서다.

### 3. 기계 게이트를 새로 만들지 않는다

연결어미 뒤 쉼표(`-고,` `-며,` `-때문에,` `-뒤,` `-므로,`) 과다는 위 초안에서 실제로 측정된
문체 문제였다. 윤문 전 16건, 윤문 후 0건이다.

그런데 이걸 잡는 임계를 이 저장소 코퍼스로 보정하면 **동작하지 않는다.** 측정해 봤다.

| 기준 | 문장당 연결어미 쉼표 비율 |
| --- | --- |
| 이 저장소 189개 글 중앙값 | 0.198 |
| p75 | 0.250 |
| p90 | 0.300 |
| 문제의 초안 | **0.250 (p75)** |

초안은 코퍼스 안에서 이상치가 아니었다. 저장소 전체가 같은 습관을 공유하기 때문이다. p90으로
임계를 잡으면 이 글은 통과하고, 중앙값으로 잡으면 글 절반이 걸린다. **자기 코퍼스를 기준으로
자기 습관을 검출할 수는 없다.**

외부 한국어 baseline과 비교하는 도구를 쓴다. `humanize-korean` 스킬의 사전 점수 shim은 LLM
호출 없이 z-score와 `risk_band`를 출력한다. 같은 초안이 `ending_comma_rate z=+4.78`로 나왔다.

```bash
python3 <humanize-korean>/scripts/prepare_monolith_input.py \
  --text "$(cat <post>)" --genre blog
```

`audit_humanizer.py`에는 이 검사를 추가하지 않았다. 임계가 근거 없이 정해지면 게이트가 통과를
보증하는 것처럼 보이지만 실제로는 아무것도 막지 못한다.

`audit_humanizer.py`는 화자 부재도 검출하지 않는다. 자동 게이트 통과를 이 문서의 체크리스트를
건너뛰는 근거로 쓰지 않는다.
