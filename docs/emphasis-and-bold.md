# 본문 강조는 판단이 걸린 문장에만 쓴다

모든 기술 글에 적용한다.

## 기준선

2026-09-13에 249개 글을 측정했다. 아래가 보강 작업을 시작하게 만든 값이다.

| 본문 볼드 개수 | 글 수 |
| --- | --- |
| 0개 | 31 |
| 1-2개 | 54 |
| 3개 이상 | 164 |
| 중앙값 | 8 |

볼드가 0개인 글은 읽는 사람이 어디를 봐야 하는지 알 수 없다. 중앙값 8개가 이 블로그의
기본 밀도이고, 3,000자 이상 글에서 0-2개는 미달로 본다.

같은 날 미달 38개 글을 보강해 `check_emphasis.py` 기준 미달은 0개가 됐다. 이 표는 갱신하지
않는다. 기준을 정한 근거이지 현재 상태 보고가 아니다.

## 볼드를 붙이는 자리

- **결론 문장의 판단부**: `이때 stream을 파괴하는 코드가 1.8.1에는 없었습니다`
- **독자가 틀리기 쉬운 지점**: `destroy()만 호출해서는 native handle이 반환되지 않습니다`
- **두 선택지를 가르는 기준**: `두 버전을 가르는 결정적 지표는 handle 잔존 수입니다`
- **대응이 없다는 사실처럼 행동을 바꾸는 제약**: `workaround가 없습니다`

## 붙이지 않는 자리

- 고유명사, 제품명, 버전 번호, 명령어. 이미 코드 스팬이나 링크로 구분된다
- 표 셀 안. 표는 그 자체가 대조 장치다
- 한 문단에 두 군데 이상. 전부 강조하면 아무것도 강조되지 않는다
- 헤딩 바로 아래 첫 문장 전체. 헤딩이 이미 그 역할을 한다

## 확인

```bash
python3 kkamji_scripts/blog/check_emphasis.py --file <post>
```

3,000자 이상인데 본문 볼드가 3개 미만이면 경고한다. 하드 게이트가 아니라 보고용이다.
글 성격상 강조할 판단이 없으면 그대로 둔다.
